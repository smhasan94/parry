# End-to-End Testing Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build an in-process async E2E test suite that verifies the full Parry flow — from SDK-style event ingestion through detection pipeline to incident creation and API retrieval — without Docker or Celery.

**Architecture:** Use HTTPX AsyncClient with FastAPI's TestClient pattern. Stand up a test Postgres database, override SQLAlchemy session + auth dependencies, and call the detection pipeline synchronously (bypassing Celery). Each test covers a distinct flow: clean event (no incident), malicious event (incident created), policy violation, and incident lifecycle.

**Tech Stack:** pytest + pytest-asyncio, HTTPX, SQLAlchemy async (test DB), FastAPI dependency overrides

### Notes

- **Database:** Tests require a running Postgres instance with a `parry_test` database. The conftest creates/drops all tables per session.
- **Celery bypass:** Detection pipeline is called directly via `run_and_persist_detections()` — no Celery broker needed.
- **Test isolation:** Each test gets its own DB session with rollback, but tables persist across the session for speed.
- **Auth override:** The HTTPX client hits real FastAPI routes with real auth middleware — no auth mocking. Tests authenticate with a real seeded API key.
